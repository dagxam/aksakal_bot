# Аксакал — Telegram-бот для живой группы

Аксакал участвует в беседе как живой собеседник: отвечает на сообщения через Telegram Reply, поэтому имя пользователя в текст ответа не добавляется.

## Уже работает

- хранение последних сообщений группы в SQLite;
- контекстные подколы через AI;
- AUTO-режим: сам выбирает Нормальный, Злой или Супер злой по текущему разговору;
- реакция на стикеры;
- получение Telegram reactions;
- режим «молчун»: после долгой тишины выбирает участника и пытается оживить чат;
- антиспам и cooldown, чтобы не долбить одного человека;
- добровольный `/profile male|female|neutral`, чтобы менять стиль шуток без угадывания пола по имени;
- `/roast` ответом на конкретное сообщение;
- AI-only ответы без готовых фраз: при сбое одной модели бот пробует следующую.

## Важное ограничение Telegram

Обычный Telegram Bot API не даёт боту список людей, которые прямо сейчас online. Поэтому «сидит в сети, но молчит» определяется косвенно: по недавним сообщениям, реакциям и стикерам.

Чтобы бот видел обычные сообщения группы, отключите Privacy Mode у BotFather (`/setprivacy`) либо назначьте бота администратором. Для событий `message_reaction` бот должен быть администратором; код уже явно запрашивает этот тип update.

## Быстрый запуск в Telegram-группе

1. В **@BotFather** откройте `/mybots` → выберите Аксакала.
2. В **Bot Settings → Group Privacy** выключите Privacy Mode (`Disable`). Иначе бот по умолчанию не видит обычный разговор группы.
3. Через **Edit Bot → Edit Botpic** (или команду `/setuserpic`) установите аватар Аксакала.
4. Добавьте бота в нужную группу и назначьте **администратором**. Это особенно важно для получения событий реакций.
5. На сервере заполните локальный `.env` реальным `TELEGRAM_BOT_TOKEN` и при необходимости `OPENAI_API_KEY`.
6. Запустите `python bot.py`. Процесс должен постоянно работать — GitHub сам по себе бота не запускает.
7. В группе отправьте `/test`. Ответ **«Аксакал жив…»** означает, что Telegram → сервер → бот работают.
8. Затем отправьте `/status` и несколько обычных сообщений. Самостоятельные шутки бот пишет не на каждое сообщение — это намеренно, чтобы не спамить.

После запуска код сам:
- удаляет старый webhook, чтобы long polling мог работать;
- регистрирует меню Telegram-команд;
- задаёт имя и описание бота.

### Если `/test` не отвечает

Смотрите консоль процесса `python bot.py`. При правильном токене в начале должно быть:
`Аксакал запущен: @username_бота`.

Если этой строки нет — бот фактически не запущен либо неверен токен.

## Запуск

Нужен Python 3.11+.

```bash
python -m venv .venv
```

Windows:

```bash
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
```

Linux/macOS:

```bash
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Заполните локальный `.env`:

```env
TELEGRAM_BOT_TOKEN=токен_от_BotFather
OPENAI_API_KEY=ваш_api_key
OPENAI_MODEL=gpt-5.6-luna
DATABASE_PATH=aksakal.db
DEFAULT_ROAST_LEVEL=3
MIN_BOT_INTERVAL_MINUTES=10
SILENCE_TRIGGER_MINUTES=180
CONTEXT_MESSAGE_LIMIT=40
AI_ENABLED=true
```

**Никогда не коммитьте реальные `TELEGRAM_BOT_TOKEN` и `OPENAI_API_KEY` в публичный GitHub.**

Запуск:

```bash
python bot.py
```

## Команды

Основное меню специально короткое:

- `/settings` — открыть кнопки режима, времени ответа и включения/выключения;
- `/status` — показать текущее состояние;
- `/roast` — вручную подколоть человека ответом на его сообщение;
- `/good` — администратор отмечает удачный AI-ответ Аксакала;
- `/bad` — администратор отмечает неудачный AI-ответ Аксакала;
- `/test` — проверить, что бот работает;
- `/start` — краткая справка.

Быстрые настройки вручную: `/hardness auto|normal|angry|super`; время — `/time 3|5|20|40|60|180`.

В `/settings` время выбирается кнопками: **3 сек, 5 сек, 20 сек, 40 сек, 1 мин, 3 мин**. Это таймер тишины: каждое новое обычное сообщение сбрасывает отсчёт. Если за выбранное время новых сообщений нет, Аксакал оценивает последнее сообщение и отвечает на него только если есть уместный повод.

Режимы: **AUTO, Нормальный, Злой, Супер злой**. AUTO сам переключается между ними по смыслу разговора. Нормальный поддерживает беседу, отвечает на вопросы и поддерживает человека по теме; Злой отвечает резко и колко; Супер злой использует самый жёсткий взрослый стёб, мат и может цепляться за противоречия и заметные ошибки в словах, оставаясь в теме разговора.

## AUTO-режим

AUTO сам выбирает один из трёх характеров ответа:

- **Нормальный** — обычный разговор, вопросы, серьёзные темы, поддержка и уместные мудрые формулировки;
- **Злой** — спор, подколы, грубоватый тон, противоречия и слабые аргументы;
- **Супер злой** — очень жёсткий взрослый стёб, когда сам разговор уже идёт в таком ключе.

При реальной грусти или угрозах бот не должен усугублять ситуацию: он остаётся по теме, поддерживает или осаживает, но не разгоняет насилие.


## Эмоциональные режимы

- **Поддержка** — если чувствуется грусть, усталость, обида или тяжёлое настроение. Roast отключается.
- **Успокоение** — если разговор становится напряжённым или злым.
- **Суровый режим** — если появляется явная грубость; Аксакал осаживает поведение, но не разжигает конфликт.
- **Мудрый режим** — для серьёзных разговоров о жизни, отношениях, доверии, дружбе и решениях.
- **Шутливый режим** — обычные контекстные подколы, стикеры, реакции и молчуны.

## Когда Аксакал вмешивается

Аксакал не отвечает на каждое сообщение. Он ждёт подходящий момент: явный повод для подкола, смешную/дерзкую реплику, напряжение, грусть, серьёзную мысль, стикер или реакцию.

- На обычное сообщение ответ генерируется только по смыслу именно этого сообщения.
- Предыдущая переписка используется только как фон и память группы.
- Ответ отправляется через Telegram Reply без повторения имени человека в самом тексте.
- На стикер бот иногда отвечает отдельным подколом про то, что пора писать словами.
- После длительной тишины бот выбирает одного из знакомых участников и пытается расшевелить всю группу.


## Бесплатный AI-резерв

Можно оставить OpenAI основным провайдером и добавить OpenRouter как резерв. Если OpenAI недоступен, Аксакал автоматически попробует бесплатный маршрут OpenRouter.

В `.env`:

```env
OPENROUTER_API_KEY=
OPENROUTER_MODEL=openrouter/free
```

Ключ создаётся в OpenRouter. Бесплатный план имеет ограничения по частоте/числу запросов, поэтому для очень активной группы он подходит прежде всего как резерв.

## Память и защита от повторов

Аксакал теперь:

- сохраняет собственные ответы в SQLite и видит их в следующем контексте;
- хранит историю сообщений группы;
- запоминает частые слова и реальные соседние фразы участников;
- ищет старые сообщения, связанные с текущей темой, без платной векторной базы;
- получает список последних собственных ответов и обязан менять лексику и конструкцию;
- проверяет новый ответ на сильное сходство с недавними и при совпадении использует другой вариант;
- при ошибке или плохом ответе одной модели переключается на следующую AI-модель; готовых фраз больше нет.


### Цепочка резервных моделей

Аксакал умеет использовать несколько AI подряд. Рекомендуемая схема:

1. OpenAI, если ключ настроен;
2. Groq + Qwen 3.8 27B как быстрый бесплатный независимый резерв;
3. OpenRouter с автоматическим failover по бесплатным моделям:
   - `qwen/qwen3.8-27b:free`
   - `deepseek/deepseek-chat-v3-0324:free`
   - `qwen/qwen3-235b-a22b-2507:free`
   - `deepseek/deepseek-r1-0528-qwen3-8b:free`
   - `openrouter/free`

Настройка:

```env
GROQ_API_KEY=
GROQ_MODEL=qwen/qwen3.8-27b

OPENROUTER_API_KEY=
OPENROUTER_MODELS=qwen/qwen3.8-27b:free,deepseek/deepseek-chat-v3-0324:free,qwen/qwen3-235b-a22b-2507:free,deepseek/deepseek-r1-0528-qwen3-8b:free,openrouter/free
```

Ключи независимы: если один сервис недоступен, бот пробует следующий. Один OpenRouter-ключ используется для всей внутренней цепочки бесплатных моделей.


### AI-only ответы

Готовых ответов в коде больше нет. Каждый автоматический ответ должен быть сгенерирован одной из подключённых AI-моделей и пройти проверку на повторы, пересказ сообщения и шаблонные формулировки. Если ответ одной модели не проходит проверку, бот пробует следующую модель. Если все AI недоступны или все ответы плохие, бот молчит вместо бессмысленной заготовки.


## Ответы на вопросы

Аксакал — не только бот для шуток. Если последнее сообщение содержит настоящий вопрос, AI должен сначала дать полезный ответ по существу. Для вопроса ответ может быть длиннее обычной реплики и занимать несколько предложений. Шутка или местная подача добавляются только после содержательного ответа и только если это уместно.

Юмор строится на конкретной детали текущего разговора, противоречии, формулировке, реальной привычке участника или связанном callback из памяти группы. Натянутые универсальные подколы не должны заменять нормальный разговор.


## Понимание reply-цепочек и людей

Бот теперь сохраняет связи Telegram Reply. Если Магомед отвечает Али, а затем разговор продолжается ещё несколькими сообщениями, генератор получает именно эту ветку как отдельный приоритетный контекст, а не только последние сообщения группы подряд.

Для каждого участника автоматически строится безопасный поведенческий профиль только из переписки группы: сколько он пишет, как часто использует стикеры и реакции, повторяющиеся выражения, последние реплики и кому чаще отвечает. Этот профиль используется для более живых callback-шуток и понимания привычек, но не для догадок о здоровье, происхождении, религии или других чувствительных качествах.

## Разнообразие юмора

Аксакал хранит последние использованные приёмы юмора и старается не повторять один и тот же способ несколько раз подряд. Доступны сухая ирония, подкол логики, сравнение, гипербола, игра слов, callback к памяти группы и — в Супер злом режиме — уместная придирка к явной ошибке. Для серьёзного вопроса или поддержки юмор может быть полностью отключён.

## AI-редактор качества

После генерации локальные фильтры проверяют повтор, пересказ сообщения, имя в начале, шаблонность и утечку внутренних рассуждений. Если настроен Groq, хороший черновик дополнительно проходит короткую вторую AI-проверку: редактор либо подтверждает его, либо возвращает более естественную финальную реплику. Ошибка редактора не блокирует уже хороший основной ответ.


## Обучение по реакциям группы

Аксакал связывает каждый свой AI-ответ с использованным приёмом юмора. Реакции на его сообщение становятся обратной связью: 😂 🤣 🔥 ❤️ 👍 👏 💯 и похожие повышают вес приёма, а 👎 🤡 🙄 😒 💩 и похожие — понижают. Если реакцию убрать или заменить, запись обновляется, а не накручивается повторно.

Обычный Reply на сообщение Аксакала тоже считается сигналом вовлечения. Явные ответы вроде «бред», «не смешно», «неправильно», «скучно» снижают оценку; нормальное продолжение разговора даёт положительный сигнал, а явно одобрительная реакция — более сильный.

При выборе следующего типа юмора учитывается общая реакция группы и усиленный сигнал от ответов, которые раньше были адресованы конкретному участнику. Один случай не должен навсегда переучить бота: оценки сглаживаются, а недавно использованные приёмы всё равно временно исключаются из повтора.

В `/status` показывается количество накопленных сигналов обучения юмору.


## Ручное обучение администратора

Администратор может ответить командой `/good` или `/bad` прямо на AI-реплику Аксакала.

- `/good` даёт сильный положительный сигнал (+2);
- `/bad` даёт сильный отрицательный сигнал (-2);
- обычные участники этими командами переучивать бота не могут;
- повторная оценка того же ответа тем же администратором заменяет предыдущую, а не накручивает статистику.

Ручная оценка влияет не только на выбор типа юмора. Последние удачные и неудачные ответы передаются AI как примеры стиля: хорошие служат ориентиром по ритму и естественности, плохие показывают, каких конструкций избегать. Они не копируются дословно и не должны переносить старые факты в новую тему.
